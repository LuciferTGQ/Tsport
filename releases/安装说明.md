# Tsport 1.0.4 Android 自用测试版

安装文件：`Tsport-1.0.4-debug.apk`，约 4.3 MB，Android 8.0 及以上。

与 1.0.0 至 1.0.3 使用相同包名和签名，可直接覆盖安装以保留训练、体重记录。建议先导出备份，不需要卸载。

## 更新内容

- 修复复制模板带入训练随记：新保存模板不含随记，加载旧模板也忽略旧随记；原日期和目标日期已有的随记均保留。
- 增加分类动作库：当天动作卡片点「存入动作库」，保存名称、组数、次数、重量和休息配置，分类可选胸、肩、背、腿、其他。编辑当天动作时也可勾选「同时保存到动作库」。
- 「添加训练动作」打开动作库，可按分类筛选、搜索名称、选择「添加到当天」或新建动作。动作库可编辑、删除；已安排的训练不随库中修改而改变，每次添加从零记录开始。
- 动作编辑支持「每组单独设置重量」，如 20、25、30、35 kg。各组重量在动作卡片展示，绿色卡片显示当前/下一组目标；计时结束和加号补记均采用对应组重量，加练沿用最后一组目标。目标修改不会改写历史实际重量。
- 完整 JSON 备份包含动作库和各组目标；兼容旧备份。保留两位小数体重、长按排序、原生后台休息提醒等已有功能。

## 在 iQOO Neo9 Pro / Android 16 / OriginOS 6 上检查

1. 覆盖安装 APK，打开 Tsport → 偏好设置，允许「休息结束系统通知」。
2. 建议继续允许「闹钟与提醒」权限。未授予时前台服务仍可计时，但没有另一条精确闹钟唤醒路径。
3. 点击「30 秒后测试后台提醒」。**下拉通知栏应立即出现“后台测试倒计时”常驻卡片**，秒数由系统显示。然后切到其他应用，等待 30 秒。
4. 到点应出现结束通知，按设置响铃/震动；点击只返回训练，不自动开始下一组。
5. 如果仍失败，点击「检查后台计时状态」，展开「查看原生运行记录」。`scheduled` 表示原生已收到计时，`foreground service started` 表示服务已启动，`fired ... source=service/alarm` 表示原生已到点并调用系统通知；这些记录可帮助区分未启动、后台未执行和系统通知未显示。
6. 如原生已有到点记录但没有横幅，检查 Tsport 系统通知设置中的悬浮通知、锁屏通知、声音/震动以及两个频道（休息结束、休息倒计时）。如后台服务被限制，检查手机 Tsport 后台耗电管理是否允许后台运行。应用内电池设置入口打开的是 Android 标准设置，OriginOS 的额外设置名称可能不同。

常驻卡片显示在通知栏，不保证获得 vivo 原子岛/原子通知专属样式。测试和训练同时进行时，常驻卡片显示最近将到点的一项，两项分别提醒。休息结束或取消后停止前台服务，释放 CPU 唤醒锁；不会在训练等待阶段永久保活。

强行停止应用会终止计时；重启手机后不补发旧提醒，回到应用时重排尚未到期的休息。

## 验证边界与校验

- 26 项逻辑测试、14 项浏览器/桥接交互测试通过。新增新旧模板随记隔离、递增组计时/补记、目标修改后保留历史、动作库分类搜索与独立编辑、刷新及备份往返；保留长按排序、两位小数体重和通知桥接验证。
- 本版未改动原生服务/接收器，未重复运行原生单元测试；1.0.2 的 8 项 Robolectric Android 16 原生计时测试已通过。
- 前端及 Android 构建通过；APK v2 签名与版本校验通过。
- 尚未连接用户的 iQOO 真机。触摸测试通过 Chrome 的触摸事件模拟执行，不等同于手机实测；原生测试也不是厂商系统的锁屏、震动或省电兼容性验收。

训练和体重只保存在本机；卸载或清除应用数据前请备份。
